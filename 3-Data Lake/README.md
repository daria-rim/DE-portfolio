# 🗺️ Data Lake: Геоаналитика пользователей социальной сети

> Построение Data Lake с многослойной архитектурой для обработки геоданных пользователей, создания аналитических витрин и системы рекомендаций друзей на основе географической близости и поведенческих паттернов.

---

## 🎯 Описание проекта
Проект представляет собой полный цикл обработки геоданных пользователей социальной сети — от сырых событий с координатами до готовых аналитических витрин и рекомендательной системы. 

**Бизнес-задачи:**
- Определение текущего местоположения пользователей и их "домашних" городов
- Анализ перемещений пользователей между городами
- Построение системы рекомендаций друзей на основе географической близости и общих интересов
- Мониторинг активности пользователей по географическим зонам

## 🏗️ Структура Data Lake
### Многоуровневая архитектура:
1. **Raw Layer** — исходные данные:
   - `/user/master/data/geo/events` — события с координатами

2. **Staging Layer** — обогащенные данные:
   - `/user/dariarim/data/analytics/geo/events_with_cities` — события с городами

3. **Data Mart Layer** — финальные аналитические витрины:
   - `/user/dariarim/data/analytics/geo/user_mart` — витрина пользователей
   - `/user/dariarim/data/analytics/geo/zone_mart` — витрина географических зон  
   - `/user/dariarim/data/analytics/geo/friend_recommendations` — рекомендации друзей
   - `/user/dariarim/data/analytics/geo/users_with_coordinates` — пользователи с координатами

### Источники данных:
- `/user/master/data/geo/events` — события с координатами пользователей
- `/user/dariarim/data/geo/cities/geo.csv` — справочник городов с координатами

## 🔄 Обновление данных
- **Периодичность:** Ежедневное обновление
- **Время запуска:** 02:00 UTC
- **Формат данных:** Parquet (колоночный, оптимизированный для аналитики)

## 📊 Ключевые метрики и инсайты
- **Актуальный город пользователя** — где находится пользователь сейчас
- **Домашний город** — город, где пользователь провел более 27 дней непрерывно
- **Количество путешествий** — сколько раз пользователь менял города
- **Рекомендации друзей** — пары пользователей с общими подписками и расстоянием до 1 км
- **Статистика по городам** — активность сообщений, реакций, подписок по неделям и месяцам

## 🔄 ETL-процесс
### Airflow DAG (`geo_analytics_dag.py`):
- **Задача 1:** `user_analytics` — создание витрины пользователей
- **Задача 2:** `zone_analytics` — создание витрины географических зон
- **Задача 3:** `friend_recommendations` — генерация рекомендаций друзей

**Все задачи выполняются параллельно** для оптимизации времени выполнения.

## 🛠 Технологический стек
- **Обработка данных:** Apache Spark (PySpark)
- **Оркестрация:** Apache Airflow
- **Хранилище:** HDFS (Hadoop Distributed File System)
- **Формат данных:** Parquet
- **Язык:** Python 3.x
- **Библиотеки:** PySpark SQL, Window Functions

## 💡 Особенности реализации
- **Геоопределение** — вычисление ближайшего города по формуле Хаверсина
- **Определение домашнего города** — анализ непрерывного пребывания (>27 дней)
- **Рекомендательная система** — поиск пар по общим подпискам и географической близости (≤1 км)
- **Эффективные оконные функции** для определения "последнего" местоположения
- **Оптимизация через фильтрацию** (только последние 1 день для тестирования, легко масштабируется)
- **Устранение дубликатов** в рекомендациях через сортированные пары пользователей
- **Поддержка временных зон** — конвертация UTC в локальное время пользователя
